# DayFrame — 推荐架构与模块说明

本文档说明**初始框架应包含哪几部分**、**各部分建议的语言与目录角色**，以及**典型场景下调用哪些工具或服务**。实现时可按 MVP 裁剪，不必一次到位。

---

## 1. 总体分层（逻辑视图）

```
┌─────────────────────────────────────────────────────────────┐
│                      Web 前端 (frontend)                      │
│  页面路由 · 上传 UI · 模板预览 · 导出截图 · （可选）本地草稿    │
└────────────────────────────┬────────────────────────────────┘
                             │ HTTPS / JSON
┌────────────────────────────▼────────────────────────────────┐
│                   后端 API (backend)                        │
│  鉴权 · 上传凭证 · 作品 CRUD · 任务编排 · 调用 AI 服务        │
└────────────────────────────┬────────────────────────────────┘
                             │
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
┌──────────────┐   ┌─────────────────┐   ┌──────────────┐
│ 对象存储       │   │ PostgreSQL       │   │ AI 推理       │
│ (R2/S3/…)     │   │ 用户·作品·任务    │   │ Vision + LLM │
└──────────────┘   └─────────────────┘   └──────────────┘
```

前期可将「后端 API」与「AI 调用」放在同一个 FastAPI 进程内；规模变大后再拆成独立 **Python AI 微服务** 或按你在产品文档中的设想引入 **Spring Boot** 主站。

---

## 2. 模块划分与职责

| 模块 | 职责摘要 |
|------|-----------|
| **frontend** | 四页流程、模板组件库、富文本/轻编辑、前端导出长图、调用后端 API |
| **backend** | REST（或 tRPC/Server Actions 若全栈 monorepo）、上传、存储 URL、作品与任务状态、调用模型 API |
| **prompts** | Vision/文案的系统提示词、风格预设、JSON schema 说明，与代码解耦便于 A/B |
| **docs** | 产品愿景、架构、API 约定、上线 checklist（本目录） |

可选后续扩展（首版可不建目录）：**worker**（异步生成、队列）、**infra**（IaC、Docker Compose）。

## 3. 各层建议技术选型

### 3.1 前端 `frontend/`

| 方面 | 建议 | 说明 |
|------|------|------|
| 框架 | **Next.js**（React） | 与你的方案一致；SSR/路由/API Route 利于一站式 MVP |
| 语言 | **TypeScript** | 模板 props、API 类型与后端契约一致 |
| UI | **任选**：Tailwind + 组件库（如 shadcn/ui） | 模板「美观」主要落在组件与主题 token |
| 模板 | **React 组件** | 每个模板接收 `photos, title, diary, captions, style` 等 |
| 导出 | **html-to-image** / dom-to-image / html2canvas | 浏览器端生成长图、便于分享截图 |
| 可选 | **Playwright 仅在后端** | 若需服务端像素级一致导出 |

### 3.2 后端 `backend/`

| 方面 | 建议 | 说明 |
|------|------|------|
| 运行时 | **Python 3.11+** | AI 生态成熟 |
| 框架 | **FastAPI** | 异步、OpenAPI 自动生成、与 ML 栈契合 |
| 存储 SDK | **boto3**（S3 兼容 R2）或 **Supabase** 官方客户端 | 按你选的存储 |
| 数据库 | **SQLAlchemy 2 + Alembic** 或 **Supabase** 直连 | PostgreSQL 迁移与版本管理 |
| 任务（可选） | **Celery + Redis** 或托管队列 | 生成较慢时异步化 |

### 3.3 AI 与外部服务（可在 backend 内或独立服务）

| 能力 | 常见调用方式 | 备注 |
|------|----------------|------|
| **图像理解** | OpenAI `gpt-4o` vision、Google Gemini 带图 API、Claude 3+ vision | 输出结构化 JSON 需 **prompt 约束 + 解析校验** |
| **文案生成** | 同上或专用文本模型 | 输入：风格 + 各图结构化描述 → 输出 title/diary/captions/hashtags |
| **对象存储** | **Cloudflare R2** / **AWS S3** / **Supabase Storage** | 预签名上传减轻后端带宽 |
| **数据库** | **PostgreSQL**（自建或 **Supabase**） | 作品、用户、异步任务状态 |

### 3.4 提示词 `prompts/`

| 内容 | 建议格式 |
|------|-----------|
| Vision 系统提示、用户模板 | `.md` 或 `.yaml` |
| 风格预设（小红书/旅行…） | 独立文件 + 版本号，便于回滚 |

## 4. 关键数据流（与工具对应）

1. **上传**  
   前端 → 后端签发 **presigned URL** → 浏览器直传 **R2/S3** → 返回 `image_url` 列表  

2. **理解图片**  
   后端从存储取可读 URL → 调用 **Vision API** → 得到每张图的结构化 JSON → 落库或缓存  

3. **生成文案**  
   后端组装「多图结构 + 用户选风格」→ **LLM** → 解析 JSON → 返回前端  

4. **排版与导出**  
   前端用 **模板组件** 渲染 → 用户可选微调文案 → **html-to-image** 等导出 PNG  

5. **历史作品（后期）**  
   **PostgreSQL** 存元数据；图片仍在对象存储；可选服务端缩略图

## 5. 不建议首版同时上的内容（可记在 backlog）

- Spring Boot 双后端（等用户量与团队熟悉度再切）  
- 多端 App（先 Web）  
- 复杂协同编辑（先单人编辑即可）

## 6. 与本仓库目录的对应关系

| 路径 | 将来主要内容 |
|------|----------------|
| `frontend/` | Next.js 应用、页面、模板组件、导出逻辑 |
| `backend/` | FastAPI、路由、存储与 DB、模型调用封装 |
| `prompts/` | 提示词与风格配置 |
| `docs/` | 本文档与产品愿景 |

实现阶段可为前后端分别添加 `package.json` / `pyproject.toml` 等；当前骨架有意保留为空，仅作边界说明。
